# AEGIS-CMO 游戏方向

把 Aegis 做成一款**单人、有限信息的现代战术指挥游戏**。优先服务喜欢策略游戏、第一次接触这套指挥界面的桌面玩家。玩家要能说清楚本方目标，分辨已观察到的事实和仍未知的信息，结算后能用同一开局试另一种选择。熟悉兵棋的玩家继续使用原有指挥工作台。

## 已交付的默认短局

| 环节 | 玩家可以做什么 |
| --- | --- |
| 开局 | 在暂停时看到本席位的主要目标、一个已有接触的分类和定位误差。点击打开详情，不推进时钟。桌面和窄屏都能关闭卡片继续操作。 |
| 演练 | 红方记录标志船的接触，决定要不要让观察机退出演练并交接。蓝方把标志船送到地图标记的交接点。两个席位按各自任务结算，都不需要开火。 |
| 结算 | 先看本方主要目标和终止原因。有对应记录才显示时间依据。目标相关事件本身并不证明目标达成。完整复盘仍可打开。 |
| 重试 | 「同条件再试」保留原种子、部署和指挥席位，回到暂停的 Tick 0。随机重开是单独选项。 |

交付沿用现有想定规则、席位命令和回放格式。[玩法契约](../../../GAMEPLAY.md#limited-information-exercise)描述当前行为。[固定种子选择测试](../../../tests/integration/exerciseChoices.test.ts)比较留场、交接和不下命令的结果。[蓝方浏览器用例](../../../tests/e2e/exerciseChoices.e2e.ts)从地图操作一直走到结算。这些检查证明操作能改变结果，不证明新人能独立发现这些选择。

## 下一步先看玩家，再扩内容

1. **先验证首局。** 在前一版和当前版分别找五位第一次接触 Aegis 的策略玩家。用同一设备、默认种子、红方指挥席位。每人只玩一个版本，不提示快捷键，不主动建议重玩。记录实际耗时、卡住的步骤和玩家原话。
2. **再做一个虚构护送短局。** 只有首局试玩过关才立项。新短局不能只把默认演练的交接点换个位置。让玩家在限时内选择保全哪份运力，用两个不同选择的可见后果验证内容是否值得保留。先用现有规则，不扩引擎。
3. **最后深化战役。** 如果玩家愿意重复游玩，再让既有战役的跨局损耗变成玩家能理解的选择。判断标准是玩家能说出上一局的哪个决定改变了下一局。想定分享先验证另一人能否导入并玩完，不先做平台。

## 建议的试玩门槛

- 五人中至少四人在三分钟实时时间内说出本方目标，并打开一条本方接触。
- 至少四人在十五分钟实时时间内完成一局，并指出决定结果的主要目标。
- 至少三人主动选择同条件再试，并说出要改哪个决定。

这些是小样本的投入门槛，不是留存估计。前两项没过，先修玩家卡住的步骤。若只有第三项没过，先检查选择是否有值得比较的代价，不靠加关卡补救。

暂不扩装备库、不加拟真参数、不做联网对战，也不把 3D 设成必经操作。保留现有装备库、沙盒、战役和想定编辑入口。真人试玩与项目负责人实玩仍未完成。
